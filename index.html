Como um programa com menu se organiza

Antes de pensar em código, precisamos entender o fluxo lógico de uma interação.

Entrada

Técnico: é o dado recebido pelo programa, normalmente por meio de input().

💡 Pense assim

É como fazer um pedido em um caixa eletrônico: você informa qual operação deseja realizar.

Processamento

Técnico: é o momento em que o programa trabalha com os dados recebidos.

💡 Pense assim

É a “cozinha” do programa: o pedido entrou e agora precisa ser preparado.

Decisão

Técnico: estruturas como if, elif e else definem qual caminho será executado.

💡 Pense assim

Um semáforo decide: verde continua, vermelho para. O programa também escolhe um caminho conforme uma condição.

Repetição

Técnico: uma estrutura como while repete um bloco enquanto uma condição for verdadeira.

💡 Pense assim

É como um caixa eletrônico voltar para a tela inicial depois de cada operação até você escolher “Sair”.

Saída

Técnico: é a informação apresentada ao usuário, por exemplo com print().

💡 Pense assim

É o recibo no fim de uma operação: o sistema informa o resultado do que foi solicitado.

Fluxo de um menu

→→→↺
Clique em uma etapa para revisar o que acontece nela.

Exemplo

opcao = input("Escolha uma opção: ")

if opcao == "1":
    print("Bem-vindo!")
elif opcao == "0":
    print("Encerrando...")
else:
    print("Opção inválida.")

Lendo o código

input() recebe a escolha. O if compara a opção com um caminho possível. O elif testa outra possibilidade. O else trata qualquer opção não prevista.

🌎 Na vida real

Menus aparecem em caixas eletrônicos, sistemas de atendimento, terminais de venda e jogos.

Por que usar funções e validar entradas

Organizar o programa significa dividir responsabilidades e proteger o fluxo contra dados inesperados.

Função

Técnico: bloco reutilizável de instruções criado com def.

💡 Pense assim

Uma função é como um setor de uma empresa: cada setor tem uma responsabilidade específica.

Chamada de função

Técnico: depois de definir a função, é preciso chamá-la para executar sua tarefa.

💡 Pense assim

Ter uma cozinha montada não prepara o prato sozinha. Alguém precisa fazer o pedido.

Validação

Técnico: verifica se uma entrada atende às regras antes de continuar.

💡 Pense assim

É como uma catraca: só deixa passar quando a condição exigida é atendida.

Sem função

print("1 - Cadastrar")
print("2 - Consultar")
print("0 - Sair")

Se esse menu precisar aparecer várias vezes, repetir o código aumenta a chance de erro.

Com função

def mostrar_menu():
    print("1 - Cadastrar")
    print("2 - Consultar")
    print("0 - Sair")

Agora a responsabilidade está centralizada: basta chamar mostrar_menu().

🤔 Pare e pense

Se o usuário digitar “9” em um menu que só possui 1, 2 e 0, o programa deve simplesmente continuar como se nada tivesse acontecido?

Não. Uma boa validação informa que a opção é inválida e permite que o usuário tente novamente, preservando o fluxo do sistema.

Construindo o menu do projeto

O programa deixa de executar uma única ação e passa a permanecer ativo enquanto o usuário quiser.

Por que usar while?

O menu deve reaparecer depois de cada operação. O while cria esse ciclo: enquanto a variável de controle permitir, o programa continua exibindo o menu e processando escolhas.

💡 Pense assim

Imagine uma loja. Depois de atender um cliente, ela não fecha automaticamente. Continua funcionando até chegar o horário de encerramento.

Variável de controle

Uma variável booleana como continuar = True pode controlar a permanência do programa no laço. Quando o usuário escolhe sair, ela muda para False.

💡 Pense assim

É como uma placa “ABERTO/FECHADO”. Enquanto estiver “ABERTO”, o atendimento continua.

Mostrar menu↓Ler opção↓Tomar decisão↓Executar função↓Voltar ao menu↺

Estrutura-base

continuar = True

while continuar:
    mostrar_menu()
    opcao = input("Escolha: ")

    if opcao == "1":
        cadastrar_produto(produtos)
    elif opcao == "0":
        continuar = False

O que está acontecendo?

O while mantém o programa em execução. Cada volta do laço exibe o menu novamente. A opção 1 chama uma função. A opção 0 altera a variável de controle e encerra o ciclo.

🌎 Na vida real

Esse padrão aparece em menus de atendimento, softwares de gestão e sistemas de cadastro.

Validação e consulta de produtos

Agora o sistema precisa ser mais confiável: validar preços, armazenar produtos e procurar informações.

Validação de preço

O sistema não deve aceitar valores menores ou iguais a zero. Enquanto o preço for inválido, deve pedir novamente.

💡 Pense assim

É como preencher um formulário que não aceita uma data impossível: o sistema pede correção antes de continuar.

Cadastro

Produto e preço são armazenados juntos para uso posterior.

💡 Pense assim

É como colocar uma ficha de produto em um arquivo: nome e preço ficam ligados à mesma ficha.

Consulta

O programa percorre os produtos cadastrados até encontrar o nome procurado ou terminar a lista.

💡 Pense assim

É como procurar um livro em uma estante, posição por posição, até encontrá-lo ou chegar ao fim.

Por que duas condições?

while i < len(produtos) and not encontrado:
    ...

A busca só continua enquanto ainda existe um produto para verificar e o item ainda não foi encontrado. Se qualquer uma dessas condições deixar de ser verdadeira, o laço para.

💡 Pense assim

Você procura uma chave em várias gavetas: para quando encontra a chave OU quando não restam mais gavetas.
